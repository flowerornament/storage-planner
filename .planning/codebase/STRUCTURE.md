## Directory Purposes

**src/core/:**
- Purpose: Reusable models and database abstractions for any purchase domain
- Contains: Models (Item, Price, Config, Decision), database layer, event log
- Key files: `models.rs` (entity definitions), `db.rs` (SQLite wrapper)
- Note: No domain-specific logic here - all JSON and generics

**src/cli/:**
- Purpose: Command implementations that enforce business logic and user workflow
- Contains: One file per command group (item, price, config, decide, etc.)
- Key files: `mod.rs` (routing), each command file has Args + handler function
- Note: Commands validate invariants before mutations (e.g., does item exist?)

**src/domains/:**
- Purpose: Pluggable domain modules for specialized purchase categories
- Contains: Currently only storage/ (can add networking/, compute/, etc.)
- Pattern: Each domain defines its own models (Node, Volume, etc.) and analysis
- Extensibility: New domains are independent - no cross-domain dependencies

**src/pricing/:**
- Purpose: Fetch product data and prices from external APIs
- Contains: API clients (Best Buy, eBay), URL parsing, graceful fallback
- Key files: `mod.rs` (trait definitions and dispatch), specific API files
- Pattern: Each API is a module implementing PriceFetcher and ProductFetcher traits

**catalog/:**
- Purpose: User-maintained reference data (not auto-generated)
- Contains: YAML files with hardware specs, software products
- Committed: Yes (checked into git)
- Note: Different from export/ (which is read-only snapshots)

**export/:**
- Purpose: Read-only snapshots for external tools, sharing, archival
- Contains: YAML exports of database state (catalog, prices, current config)
- Generated: Yes (by `sp sync`)
- Committed: Optional (for sharing decisions)

**archive/:**
- Purpose: User-created decision documents and topology proposals
- Contains: Markdown decisions, YAML proposals, topology definitions
- Generated: No (user-managed)
- Committed: Yes

**migrations/:**
- Purpose: Manual database migrations (if needed)
- Currently: Empty (schema defined inline in `core/db.rs` as SCHEMA constant)
- Future: For complex schema changes

**.sp/:**
- Purpose: Runtime database and state
- Contains: `decisions.db` (SQLite file with all mutable state)
- Generated: Yes (auto-created on first `sp init` or first command)
- Committed: No (in .gitignore)

## Key File Locations

**Entry Points:**
- `src/main.rs`: CLI entry point - parses args, dispatches to Cli::run()
- `src/lib.rs`: Library exports for external consumption

**Configuration:**
- `Cargo.toml`: Rust dependencies, binary target, linting rules
- `rust-toolchain.toml`: Rust 1.81 (or later) requirement
- `.env` files: Not used (all config via args and env vars)

**Core Logic:**
- `src/core/models.rs`: Entity definitions (Item, Price, Config, Decision)
- `src/core/db.rs`: Database wrapper with schema (lines 100+)
- `src/core/events.rs`: Event log operations and queries

**Testing:**
- Tests inline in source files (look for `#[cfg(test)]` mod blocks)
- `src/core/models.rs`: Tests for model creation, serialization
- `src/core/events.rs`: Tests for event recording and queries
- `src/core/db.rs`: Tests for transaction behavior
- Run with: `cargo test` (defined in justfile as `just test`)

## Naming Conventions

**Files:**
- `snake_case.rs`: Source files (e.g., `item.rs`, `url_parser.rs`)
- Module organization: Group related commands in one file (e.g., `item.rs` has all item subcommands)

**Directories:**
- `snake_case/`: Module directories (e.g., `src/cli/`, `src/domains/storage/`)
- User-created: kebab-case (e.g., `2026-01-30-option-a-simple-ssd.yaml`)

**Rust Identifiers:**
- Structs: PascalCase (Item, Configuration, PriceSource)
- Functions: snake_case (fetch_product, parse_url, current_actor)
- Enums: PascalCase with variants (EventType::Created, ItemCondition::New)
- Constants: SCREAMING_SNAKE_CASE (SCHEMA in db.rs)

**Command Names:**
- Subcommands: lowercase (item, price, config, decide)
- Subcommand actions: lowercase (add, list, show, create, choose)
- Short flags: `-d` (dir), `-f` (format)
- Long flags: `--url`, `--price`, `--condition`, `--source`

## Where to Add New Code

**New CLI Command:**
1. Create new file: `src/cli/new_command.rs`
2. Define args struct (using `clap::Args`) and subcommand enum
3. Implement handler function (takes args, returns `Result<()>`)
4. Add to `Commands` enum in `src/cli/mod.rs`
5. Import and wire in mod.rs dispatch logic
6. Example pattern: Look at `src/cli/item.rs` structure

**New Domain Module:**
1. Create directory: `src/domains/new_domain/`
2. Create `mod.rs` with public exports
3. Create `models.rs` with domain-specific types (JSON-serializable)
4. Create `analysis.rs` with domain calculations (optional)
5. Export from `src/domains/mod.rs`
6. Use in Configuration.domain_data (JSON field) and Configuration.domain field
7. Example: `src/domains/storage/` is the template

**New Pricing Integration:**
1. Create new file: `src/pricing/new_retailer.rs`
2. Implement `PriceFetcher` trait (fetch by query)
3. Implement `ProductFetcher` trait (fetch by URL identifiers)
4. Add availability check (e.g., check for API key env var)
5. Export from `src/pricing/mod.rs`
6. Add to dispatcher in `src/pricing/mod.rs::fetch_product()`
7. Update URL parser if new URL pattern: `src/pricing/url_parser.rs`

**New Database Table/Field:**
1. Add column/table to SCHEMA constant in `src/core/db.rs`
2. Update model in `src/core/models.rs` (add field, update insert/from_row)
3. Update event types if needed in EventType enum
4. Migration: Old databases auto-upgrade on next `sp init`
5. Run: `cargo test` to ensure database tests still pass

**New Test:**
1. Add to `#[cfg(test)] mod tests` block in same file as code being tested
2. Use `Database::open_memory()` for in-memory test databases
3. Call `db.migrate()` to initialize test schema
4. Pattern: See tests in `src/core/events.rs` for transaction examples

## Special Directories

**target/:**
- Purpose: Compiled artifacts (debug and release binaries)
- Generated: Yes (by cargo build/test)
- Committed: No (in .gitignore)

**.sp/:**
- Purpose: Runtime state (SQLite database)
- Generated: Yes (auto-created, location configurable via `$SP_DIR`)
- Committed: No (in .gitignore)

**export/:**
- Purpose: Read-only YAML snapshots of database state
- Generated: Yes (by `sp sync`)
- Committed: Optional (useful for sharing/review)

**archive/:**
- Purpose: User-created decision documents
- Generated: No (user creates these)
- Committed: Yes (historical record)
