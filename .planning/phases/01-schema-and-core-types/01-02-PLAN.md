  <name>Task 2: Implement undo/redo engine</name>
  <files>src/core/undo.rs, src/core/mod.rs</files>
  <action>
**Create `src/core/undo.rs`** with the undo/redo engine:

1. **`pub fn undo(db: &mut Database) -> Result<String>`** -- returns the summary of the undone action:
   a. Start a transaction
   b. Get `current_sequence` from undo_pointer
   c. If current_sequence < 1: `bail!("Nothing to undo")`
   d. Get event at current_sequence: `SELECT * FROM events WHERE sequence = ?1`
   e. Apply the undo based on event_type suffix:
      - `.created` -> DELETE the entity: `DELETE FROM {entity_type}s WHERE id = ?1` (pluralize entity_type for table name)
      - `.deleted` -> Re-INSERT from before_state: Parse JSON, insert row back into the table
      - `.updated` -> Restore before_state: Parse JSON, UPDATE the entity with before_state values
      - `.set_active` -> Restore before active state from before_state
   f. Decrement undo_pointer: `UPDATE undo_pointer SET current_sequence = ?1 WHERE id = 1` (set to current_sequence - 1)
   g. Commit transaction
   h. Return `format!("Undone: {}", event.summary)`

2. **`pub fn redo(db: &mut Database) -> Result<String>`** -- returns the summary of the redone action:
   a. Start a transaction
   b. Get `current_sequence` from undo_pointer
   c. Get max sequence: `SELECT COALESCE(MAX(sequence), 0) FROM events`
   d. If current_sequence >= max_sequence: `bail!("Nothing to redo")`
   e. Get event at current_sequence + 1
   f. Apply the redo based on event_type suffix:
      - `.created` -> Re-INSERT from after_state
      - `.deleted` -> DELETE the entity
      - `.updated` -> Apply after_state
      - `.set_active` -> Apply after active state from after_state
   g. Increment undo_pointer
   h. Commit transaction
   i. Return `format!("Redone: {}", event.summary)`

3. **`pub fn can_undo(conn: &Connection) -> Result<bool>`** -- returns true if current_sequence >= 1.

4. **`pub fn can_redo(conn: &Connection) -> Result<bool>`** -- returns true if current_sequence < max(sequence).

5. **Helper functions** (private):
   - `fn get_undo_pointer(tx: &Transaction) -> Result<i64>` -- reads current_sequence
   - `fn get_event_at_sequence(tx: &Transaction, seq: i64) -> Result<Event>` -- fetches event by sequence
   - `fn restore_entity(tx: &Transaction, entity_type: &str, json_state: &str) -> Result<()>` -- parses JSON and INSERTs row back into appropriate table. Must handle all entity types: topology, node, volume, dataset, placement, link, sync_regime.
   - `fn delete_entity(tx: &Transaction, entity_type: &str, entity_id: &str) -> Result<()>` -- DELETEs from appropriate table by id.
   - `fn update_entity(tx: &Transaction, entity_type: &str, entity_id: &str, json_state: &str) -> Result<()>` -- parses JSON and UPDATEs appropriate table.
   - `fn table_for_entity(entity_type: &str) -> &str` -- maps entity_type to table name: "topology"->"topologies", "node"->"nodes", "volume"->"volumes", "dataset"->"datasets", "placement"->"placements", "link"->"links", "sync_regime"->"sync_regimes".

6. **For restore_entity and update_entity**, use a generic approach:
   - Parse the JSON string into a `serde_json::Value`
   - Extract column names and values from the JSON object
   - Build a dynamic INSERT or UPDATE SQL statement
   - This avoids duplicating the column list for every entity type
   - Example for INSERT: `INSERT INTO {table} ({col1}, {col2}, ...) VALUES (?1, ?2, ...)`
   - Example for UPDATE: `UPDATE {table} SET {col1} = ?1, {col2} = ?2, ... WHERE id = ?N`

**IMPORTANT implementation notes:**
- The undo/redo engine does NOT record its own events. Undo/redo are meta-operations that move the pointer -- they don't create new event rows.
- The `db.transaction()` method takes `&mut Database` and returns `Result<T>`. The undo/redo functions should use `db.transaction(|tx| { ... })`.
- For Phase 1, undo/redo only supports topology entities (topology, node, volume, dataset, placement, link, sync_regime). Old entity types (item, price, configuration, decision) are NOT undoable.
