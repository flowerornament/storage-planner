Define Event struct:
```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct Event {
    pub id: String,
    pub sequence: i64,
    pub event_type: String,      // e.g. "topology.created", "topology.deleted", "topology.updated"
    pub entity_type: String,     // e.g. "topology", "node", "volume"
    pub entity_id: String,
    pub summary: String,         // human-readable: "Created topology 'my-setup'"
    pub before_state: Option<String>,  // JSON snapshot, None for creates
    pub after_state: Option<String>,   // JSON snapshot, None for deletes
    pub source: EventSource,
    pub actor: String,
    pub timestamp: DateTime<Utc>,
}
```
Add `from_row(row: &Row) -> rusqlite::Result<Self>` for reading events back.

Key functions:

**record_event(tx, event_type, entity_type, entity_id, summary, before_state, after_state, source) -> Result<Event>**
- Gets next sequence: `SELECT COALESCE(MAX(sequence), 0) + 1 FROM events`
- But FIRST: check undo_pointer. If current_sequence < max(sequence), DELETE all events with sequence > current_sequence (clear redo stack on new action)
- Then read current_sequence from undo_pointer to ensure we clear properly
- Insert event with new sequence
- Update undo_pointer to new sequence
- Actor comes from `current_actor()` helper (reads $USER env var, defaults to "unknown")
- Returns the created Event

**undo(db: &mut Database) -> Result<String>**
- Within a transaction:
  1. Read current_sequence from undo_pointer
  2. If current_sequence < 1, bail!("Nothing to undo")
  3. Get event at current_sequence: `SELECT * FROM events WHERE sequence = ?`
  4. Based on event_type suffix:
     - ".created" -> DELETE the entity: `DELETE FROM {entity_type}s WHERE id = ?` (pluralize table name by appending 's', but handle "sync_regime" -> "sync_regimes" correctly)
     - ".deleted" -> restore from before_state: parse JSON, INSERT back into table
     - ".updated" -> restore from before_state: parse JSON, UPDATE entity with before_state values
  5. Decrement undo_pointer: `UPDATE undo_pointer SET current_sequence = current_sequence - 1`
  6. Return the event summary (for display: "Undone: Created topology 'my-setup'")

**redo(db: &mut Database) -> Result<String>**
- Within a transaction:
  1. Read current_sequence from undo_pointer
  2. Check if event exists at current_sequence + 1. If not, bail!("Nothing to redo")
  3. Get event at current_sequence + 1
  4. Based on event_type suffix:
     - ".created" -> re-insert from after_state
     - ".deleted" -> DELETE entity again
     - ".updated" -> apply after_state
  5. Increment undo_pointer
  6. Return the event summary

**Helper: restore_entity_from_json(tx, entity_type, json_state) -> Result<()>**
This is the workhorse for undo/redo. It deserializes JSON back into the correct model struct and calls insert(). Use a match on entity_type:
- "topology" -> serde_json::from_str::<Topology>(json)?.insert(tx)?
- "node" -> serde_json::from_str::<Node>(json)?.insert(tx)?
- etc. for all 7 entity types

**Helper: update_entity_from_json(tx, entity_type, entity_id, json_state) -> Result<()>**
For undo of updates — DELETE then INSERT (simpler than building UPDATE for each entity type, and within a transaction it's atomic).

**Helper: delete_entity(tx, entity_type, entity_id) -> Result<()>**
Match on entity_type, DELETE FROM {table} WHERE id = ?. Handle table name mapping: "topology" -> "topologies", "sync_regime" -> "sync_regimes", etc.

**Helper: current_actor() -> String**
Read std::env::var("USER").unwrap_or_else(|_| "unknown".to_string())

**Helper: entity_table_name(entity_type: &str) -> &str**
Maps entity_type to SQL table name. "topology"->"topologies", "node"->"nodes", "volume"->"volumes", "dataset"->"datasets", "placement"->"placements", "link"->"links", "sync_regime"->"sync_regimes".

**src/cli/topology.rs** — `sp topology {create,list,show,set-active,delete}`:
This is the ONE fully working entity command in Phase 1. It demonstrates the full pattern: CRUD + event logging + undo/redo.

TopologyCommands enum:
- `Create { name: String, #[arg(long, short)] description: Option<String> }` — Creates topology, records "topology.created" event with after_state=topology JSON, summary="Created topology '{name}'"
- `List` — Lists all topologies (id, name, active status, created_at). Respects --format.
- `Show { name: String }` — Shows topology details. Just the topology row for now (node/volume counts come in Phase 2).
- `SetActive { name: String }` — Sets topology as active (clears other is_active flags first in a transaction). Records "topology.updated" event with before/after state.
- `Delete { name: String }` — Deletes topology. Records "topology.deleted" event with before_state=topology JSON. CASCADE handles children.

For each mutating command (create, set-active, delete), the pattern is:
1. Open transaction
2. Do the mutation
3. Call `record_event(tx, ...)` with appropriate before/after state
4. Commit
5. Print confirmation

For `create`: Auto-set as active if it's the first topology (no other topologies exist).
