  <action>
  Create `src/cli/export.rs` implementing `sp export` (TOPO-11) and `sp import` (TOPO-10).

  **Note:** This plan uses serde_yaml_ng which is added to Cargo.toml by Plan 06-01. If executing in wave 1 before 06-01 completes, add `serde_yaml_ng = "0.10"` to Cargo.toml yourself. If 06-01 already ran, it's already there.

  **YAML topology structure:**
  Define a serializable struct for the full topology export:
  ```rust
  #[derive(Serialize, Deserialize)]
  struct TopologyExport {
      topology: TopologyData,
      nodes: Vec<NodeData>,
      volumes: Vec<VolumeData>,
      datasets: Vec<DatasetData>,
      placements: Vec<PlacementData>,
      links: Vec<LinkData>,
      sync_regimes: Vec<SyncRegimeData>,
  }
  ```
  Each `*Data` struct mirrors the model struct but with all fields serializable. For the default (identity-preserving) export, include `id` fields. For `--template` export, use `#[serde(skip_serializing_if = "Option::is_none")]` and set ids to None.

  A simpler approach: use the existing model structs (Topology, Node, etc.) directly since they already derive Serialize/Deserialize. For --template mode, create a separate pass that clears id fields before serialization, or use a wrapper with `#[serde(skip)]` on id fields.

  **Recommended approach:** Define lean data structs (TopologyData, NodeData, etc.) without the id and topology_id fields for template mode, and with them for full mode. Use From trait to convert between model structs and data structs.

  **sp export <topology> [--template] [--only=nodes,volumes] [--output=<file>]:**
  - Resolve topology by name/UUID
  - Load all entities: nodes, volumes, datasets, placements, links, sync_regimes for that topology_id
  - Build TopologyExport struct
  - If --template: strip all UUIDs (id, topology_id, node_id, volume_id, dataset_id, etc.) -- these become None/empty, import will generate new ones
  - If --only: include only the specified entity types (comma-separated: nodes, volumes, datasets, placements, links, sync_regimes)
  - Serialize to YAML via serde_yaml_ng::to_string
  - If --output: write to file. Otherwise: print to stdout
  - Print success message to stderr if writing to file (so stdout stays clean for piping)

  **sp import <file> [--name=<new-name>]:**
  - Read YAML file, deserialize into TopologyExport
  - Generate new UUIDs for ALL entities (reuse fork's ID remapping pattern from topology.rs fork function):
    - Create HashMap<String, String> mapping old IDs to new UUIDs
    - First pass: generate new IDs for topology, all nodes, volumes, datasets, placements, links, sync_regimes
    - Second pass: remap all foreign key references (node_id, volume_id, dataset_id, etc.) using the map
  - If --name provided: use it as the new topology name. Otherwise use the name from YAML (append "-imported" if name already exists)
  - Insert topology first, then nodes, volumes, datasets, placements, links, sync_regimes in dependency order
  - All inserts in a single transaction
  - Record events: "topology.imported" for the new topology (source: import)
  - Print success: "Imported topology: {name} with N nodes, N volumes, N datasets"

  **Wire into src/cli/mod.rs:**
  - Add `mod export;` declaration
  - Add to Commands enum:
    ```rust

    Export { topology: String, #[arg(long)] template: bool, #[arg(long)] only: Option<String>, #[arg(long, short)] output: Option<PathBuf> },
    /// Import topology from YAML file
    Import { file: PathBuf, #[arg(long)] name: Option<String> },
    ```
  - Add match arms in Cli::run()

  **Per user decisions (LOCKED):**
  - Standalone `sp diagram` command (not a flag on show)
  - Two perspectives: --tree and --network
  - Claude's discretion on rendering implementation

  **sp diagram [--topology=<topo>] [--tree|--network]:**
  Default: --tree if neither specified.

  **--tree mode (node-volume-dataset hierarchy):**
  Hand-roll ASCII diagram using box-drawing characters (per CLI UX guidelines):
  ```
  my-topology
  ├── mac-mini (desktop, office)
  │   ├── internal-ssd [2TB, apfs]
  │   │   └── documents (500GB, critical)
  │   └── external-ssd [4TB, apfs]
  │       ├── photos (2TB, important)
  │       └── media (1.5TB, normal)
  └── nas-backup (nas, closet)
      └── nas-volume [8TB, ext4, raid1]
          ├── documents (replica)
          └── photos (replica)
  ```

  Implementation:
  - Resolve topology
  - Load nodes, volumes (grouped by node_id), placements + datasets (grouped by volume_id)
  - For each node: show name, role, location
  - For each volume under node: show name, capacity (formatted human-readable: GB/TB), filesystem
  - For each dataset placed on volume: show name, size or role (primary/replica)
  - Use tree connector characters: `├──`, `└──`, `│   `, `    ` for proper indentation
  - Handle last-item detection for correct connector choice

  **--network mode (link topology between nodes):**
  Show nodes as boxes with links between them:
  ```
  Network Topology: my-topology

  mac-mini (office) ──[thunderbolt, 5GB/s]──> nas-backup (closet)
  mac-mini (office) ──[wifi, 100MB/s]──> cloud-backup (remote)
  nas-backup (closet) ──[ethernet, 1GB/s]──> offsite (garage)

  Nodes: 4  Links: 3
  ```

  Implementation:
  - Resolve topology
  - Load nodes and links
  - For each link: format as `source (location) ──[type, bandwidth]──> target (location)`
  - Format bandwidth human-readable: bytes/sec -> KB/s, MB/s, GB/s
  - Show summary counts at bottom
  - If no links: "No network links defined"
