  **sp status -- full health report:**

  Sections in display order:

  1. **Problems (highlighted at top, only if any exist):**
     - Run inline mini-analysis on current topology (redundancy, capacity) -- the pure functions are fast, per research/discretion
     - Count datasets with insufficient copies or locations
     - Count volumes projected full within 6 months
     - Count decisions open for 30+ days
     - Display alerts in red/yellow: "2 datasets at risk", "1 volume projected full in 3 months", "1 decision open 45 days"
     - If no problems: skip this section entirely (quiet when healthy)

  2. **Current Topology:**
     - Name, tag, description (truncated)
     - Entity counts: N nodes, N volumes, N datasets, N placements, N links, N sync regimes
     - Quick stats from analysis: redundancy score, capacity score

  3. **Open Decisions:**
     - Query: `SELECT * FROM decisions WHERE status IN ('draft', 'open') ORDER BY created_at`
     - Table: Title | Status | Constraints | Topologies Considered | Age (days)
     - If none: "No open decisions"

  4. **Catalog Stats:**
     - Total items, total price observations
     - Items by category (category: count)
     - Latest price observation date

  5. **Recent Activity:**
     - Last 5 events: `SELECT * FROM events ORDER BY sequence DESC LIMIT 5`
     - Display: timestamp, summary (one line each)

  **JSON mode (--format=json):**
  Serialize all sections as a structured JSON object with keys: problems, current_topology, open_decisions, catalog_stats, recent_activity.

  **Output structure (action-oriented, per Claude's discretion):**

  The output is a single text document printed to stdout. Structure:

  ```
  # Storage Planner (sp) - Agent Guide

  ## Quick Start

  Run `sp status` to see the current state of the system.

  ## Core Workflow

  ### 1. Explore the Current State
  ```
  sp status                           # System health overview
  sp current                          # Current topology
  sp topology show <name> --tree      # Full topology tree
  sp analyze                          # Combined analysis dashboard
  ```

  ### 2. Work with Topologies
  ```
  sp topology list                    # See all topologies
  sp topology fork <name> <new-name>  # Fork for exploration
  sp topology tag <name> exploring    # Tag the fork
  sp node add <name> --topology=<t> --role=<r> --location=<loc>
  sp volume add <name> --node=<n> --capacity=<bytes>
  sp dataset add <name> --topology=<t> --size=<bytes> --criticality=<level>
  sp placement add --dataset=<d> --volume=<v>
  ```

  ### 3. Analyze Options
  ```
  sp analyze redundancy               # Check dataset copy requirements
  sp analyze capacity                  # Project storage growth
  sp analyze rpo                      # Check sync schedule compliance
  sp analyze failure --node=<name>    # Simulate node failure
  sp analyze bandwidth                # Check link capacity for sync
  sp analyze cost                     # One-time + recurring costs
  sp analyze cost --tco=3yr           # Total cost of ownership
  ```

  ### 4. Track Decisions
  ```
  sp decision create "Decision title"
  sp decision constrain <dec> --type=budget --max=1000
  sp decision consider <dec> --topology=<t>
  sp decision open <dec>
  sp analyze compare --a=<t1> --b=<t2>    # Side-by-side
  sp analyze constraints --decision=<dec>  # Check constraints
  sp decision choose <dec> --topology=<t> --rationale="..."
  ```

  ### 5. Manage Catalog
  ```
  sp catalog add "Product Name" --category=<cat> --url=<url>
  sp catalog price add <item> --amount=<cents> --type=one-time
  sp catalog search <query>
  ```

  ## Output Formats

  All commands support `--format=json` for structured output.

  ## Key Concepts

  - **Topology**: A named configuration of nodes, volumes, datasets, links, and sync regimes
  - **Current topology**: The active baseline (only one at a time)
  - **Tags**: current, exploring, archived (or untagged)
  - **Decisions**: Track which topologies are being compared and why
  - **Catalog**: Items and price observations linked to topology entities
  ```
