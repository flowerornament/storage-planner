  Add bandwidth and cost analysis functions to the existing analysis module. These are pure functions following the established pattern (take data, return reports).

  **Bandwidth analysis (ANLZ-06):**

  Define types:
  ```rust
  pub struct BandwidthReport {
      pub results: Vec<BandwidthResult>,
      pub score: f64,  // 0.0-1.0 (fraction of sync regimes with adequate bandwidth)
  }

  pub struct BandwidthResult {
      pub sync_regime_name: String,
      pub dataset_name: String,
      pub dataset_size_bytes: i64,
      pub source_node: String,
      pub target_node: String,
      pub link_bandwidth_bytes_sec: Option<i64>,  // None if no direct link
      pub required_bandwidth_bytes_sec: i64,  // dataset_size / sync_interval_seconds
      pub status: BandwidthStatus,
  }

  pub enum BandwidthStatus {
      Adequate,   // link bandwidth >= required
      Tight,      // link bandwidth is 50-100% of required
      Insufficient, // link bandwidth < 50% of required
      NoLink,     // no direct link between source and target nodes
  }
  ```

  `pub fn analyze_bandwidth(sync_regimes: &[SyncRegimeWithContext], links: &[Link]) -> BandwidthReport`:
  - For each sync regime, find the direct link between source node and target node (match by node IDs via volumes)
  - Compute required bandwidth: dataset_size_bytes / sync_interval_seconds (use cron_interval_hours * 3600 for schedule-based, or treat continuous as needing full bandwidth for the dataset size in 1 hour)
  - If no direct link exists: status = NoLink
  - If link bandwidth is None: treat as unknown, status = NoLink
  - Compare link bandwidth vs required: Adequate (>= 100%), Tight (50-100%), Insufficient (< 50%)
  - Score = fraction of sync regimes with Adequate or Tight status
  - NOTE: Simple direct-link check only, NOT path-finding (per research: "that's v2 ANLZ-10")

  Need to load SyncRegimeWithContext (already exists from Phase 4) and also load the source/target volume's node IDs. The SyncRegimeWithContext struct already has source_node_id and target_node_id -- check if it does. If not, the loader needs to JOIN to get node IDs for source and target volumes.

  **Cost analysis (ANLZ-07):**

  Define types:
  ```rust
  pub struct CostReport {
      pub entities: Vec<EntityCost>,  // per-entity breakdown
      pub one_time_total_cents: i64,
      pub monthly_total_cents: i64,
      pub annual_total_cents: i64,
  }

  pub struct EntityCost {
      pub entity_type: String,  // "node" or "volume"
      pub entity_name: String,
      pub item_name: Option<String>,
      pub item_id: Option<String>,
      pub one_time_cents: i64,
      pub monthly_cents: i64,
      pub annual_cents: i64,
  }
  ```

  `pub fn analyze_cost(entities: &[EntityCost]) -> CostReport`:
  - Sum one_time, monthly, annual across all entities
  - Return CostReport with per-entity list and totals
  - This is a simple aggregation -- the caller (CLI) is responsible for loading entities and looking up latest prices

  The CLI will need to:
  1. Load all nodes and volumes for the topology
  2. For each entity with an item_id, query the latest price from the prices table
  3. Build EntityCost entries based on price_type ("one-time" -> one_time_cents, "monthly" -> monthly_cents, "annual" -> annual_cents)
  4. Use latest observation (most recent) per user decision

  Add helper: `pub fn compute_tco_cents(report: &CostReport, years: u32) -> i64`:
  - TCO = one_time_total + (monthly_total * 12 * years) + (annual_total * years)

  Add unit tests:
  - test_bandwidth_adequate: link with plenty of bandwidth
  - test_bandwidth_insufficient: link too slow
  - test_bandwidth_no_link: no link between nodes
  - test_cost_aggregation: multiple entities, verify totals
  - test_tco_projection: verify 3-year calculation

<task type="auto">
  <name>Task 2: Bandwidth and cost CLI subcommands</name>
  <files>src/cli/analyze.rs</files>
  <action>
  Add Bandwidth and Cost variants to the existing AnalyzeCommands enum.

  **AnalyzeCommands additions:**
  ```rust
  /// Check if network links support sync regime bandwidth requirements
  Bandwidth {
      /// Target topology (defaults to current)
      #[arg(long)]
      topology: Option<String>,
  },
  /// Analyze topology cost (one-time + recurring from catalog items)
  Cost {
      /// Target topology (defaults to current)
      #[arg(long)]
      topology: Option<String>,
      /// Show category summary instead of per-entity breakdown
      #[arg(long)]
      summary: bool,
      /// Show total cost of ownership projection (e.g., --tco=3yr)
      #[arg(long, value_name = "PERIOD")]
      tco: Option<String>,
  },
  ```

  **Bandwidth handler (run_bandwidth):**
  - Resolve topology via resolve_active_topology
  - Load sync regimes with context via load_sync_regimes_with_context
  - Load links: `SELECT * FROM links WHERE topology_id = ?1`
  - Call analyze_bandwidth(sync_regimes, links)
  - Display results as table: Sync Regime | Dataset | Source -> Target | Required BW | Link BW | Status
  - Color status: green for Adequate, yellow for Tight, red for Insufficient/NoLink
  - Show overall score at bottom
  - Exit code 1 if any Insufficient or NoLink results (per D028 pattern)
  - JSON mode: serialize BandwidthReport

  **Cost handler (run_cost):**
  - Resolve topology via resolve_active_topology
  - Load all nodes: `SELECT * FROM nodes WHERE topology_id = ?1`
  - Load all volumes: `SELECT * FROM volumes WHERE topology_id = ?1`
  - For each entity (node or volume) with item_id not NULL:
    - Query latest price: `SELECT * FROM prices WHERE item_id = ?1 ORDER BY observed_at DESC LIMIT 1`
    - Build EntityCost based on price_type
  - Entities without item_id: include with zero costs (show as "No catalog item linked")
  - Call analyze_cost to get CostReport

  **Default display (per-entity breakdown):**
  - Section "One-Time Costs:" -- table of entities with one-time prices
  - Section "Recurring Costs:" -- table of entities with monthly/annual prices
  - Section "Totals:" -- one-time total, monthly total, annual total
  - Entities with no catalog item linked shown dimmed

  **--summary flag (category summary):**
  - Group EntityCost entries by entity_type (nodes vs volumes)
  - Show: Category | Count | One-Time | Monthly | Annual
  - Show totals row

  **--tco flag:**
  - Parse period: extract number and unit (e.g., "3yr" -> 3 years, "5yr" -> 5 years)
  - If provided, add a "Total Cost of Ownership ({N}yr):" line showing compute_tco_cents result
  - Bail with helpful message if period format is invalid

  - JSON mode: serialize CostReport with optional tco_cents field

  Update the combined dashboard handler (sp analyze with no subcommand) to include a one-line cost summary if any catalog items are linked (e.g., "Cost: $559 one-time, $0/mo recurring").

  Wire new subcommands into the run() function's match on AnalyzeCommands.
