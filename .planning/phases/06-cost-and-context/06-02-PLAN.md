<task type="auto">
  <name>Task 1: Catalog item commands (add, show, list, search)</name>
  <files>src/cli/catalog.rs, src/cli/mod.rs</files>
  <action>
  Create `src/cli/catalog.rs` with CatalogCommands enum and handler function, following the established CLI module pattern (see src/cli/node.rs as template).

  **Command structure:**
  ```
  sp catalog add <name> --category=<cat> [--specs='{"key":"val"}'] [--url=<url>] [--notes=<text>]
  sp catalog show <item>
  sp catalog list [--category=<cat>]
  sp catalog search <query>
  sp catalog price add <item> --amount=<cents> [--source=<src>] [--condition=<cond>] [--type=<price_type>] [--currency=<cur>]
  sp catalog price list <item>
  ```

  **CatalogCommands enum:**
  - Add { name, category (required), specs (optional JSON string, default "{}"), url (optional), notes (optional) }
  - Show { item: String } -- name or UUID prefix
  - List { category: Option<String> }
  - Search { query: String }
  - Price(PriceCommands) -- nested subcommand

  **PriceCommands enum:**
  - Add { item: String, amount: i64 (amount in cents), source (default "manual"), condition (default "new"), price_type (default "one-time", value_name="TYPE"), currency (default "USD") }
  - List { item: String }

  **Add item handler:**
  - Parse specs JSON string into serde_json::Value (bail on invalid JSON)
  - Create CatalogItem via ::new(), set category, specs, url, notes
  - Insert in transaction, record "catalog_item.created" event with after_state
  - Print success: "Added item: {name} ({id_prefix})" or JSON

  **Show item handler:**
  - Resolve item via resolve_catalog_item
  - Query latest price: `SELECT * FROM prices WHERE item_id = ?1 ORDER BY observed_at DESC LIMIT 1`
  - Query price count: `SELECT COUNT(*) FROM prices WHERE item_id = ?1`
  - Display: name, category, specs (formatted), url, notes, latest price (formatted as dollars), price observation count
  - JSON mode: include full item object with latest_price nested

  **List items handler:**
  - If category provided: `SELECT * FROM catalog_items WHERE category = ?1 ORDER BY name`
  - Otherwise: `SELECT * FROM catalog_items ORDER BY name`
  - Display as table: Name | Category | URL (truncated) | Latest Price
  - For each item, query latest price with a subquery or separate query
  - JSON mode: array of item objects

  **Search items handler:**
  - `SELECT * FROM catalog_items WHERE name LIKE ?1 OR category LIKE ?1 OR notes LIKE ?1 ORDER BY name`
  - Use `%{query}%` pattern for LIKE
  - Display same table format as list
  - JSON mode: array of matching items

  **Wire into src/cli/mod.rs:**
  - Add `mod catalog;` declaration
  - Add `Catalog` variant to Commands enum: `#[command(subcommand)] Catalog(catalog::CatalogCommands)`
  - Add match arm in Cli::run(): `Commands::Catalog(cmd) => { let mut db = open_db(&db_path)?; catalog::run(cmd, &mut db, format) }`

  Follow CLI UX guidelines: success messages use green styling, errors are actionable, tables use console crate formatting.
  </action>
  <verify>
  `cargo build` succeeds. `cargo test` passes. Manual test: `sp catalog add "Samsung 870 EVO 4TB" --category=ssd --url="https://example.com"` creates item. `sp catalog list` shows it. `sp catalog show "Samsung 870 EVO 4TB"` displays details. `sp catalog search "Samsung"` finds it.
  </verify>
  <done>
  CAT-01 (add item), CAT-02 (show with price history), CAT-03 (list with category filter), CAT-04 (search) are implemented. All commands support text and JSON output.
  </done>
</task>
