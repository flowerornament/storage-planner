**src/domains/storage/analysis.rs:** Create this file with:

1. **PlacementWithContext struct** -- enriched placement data loaded via JOIN:
   - Fields: placement_id, dataset_id, dataset_name, volume_id, volume_name, node_id, node_name, node_location, role, capacity_bytes, usable_bytes (Option), size_bytes, growth_rate_bytes_month (Option), criticality, min_copies, min_locations, max_rpo_hours (Option)
   - Include a `load_placements_with_context(db: &Database, topology_id: &str) -> Result<Vec<PlacementWithContext>>` function that does a single JOIN query across placements + datasets + volumes + nodes. Use block-scoped prepared statements per D023 pattern.

2. **RedundancyReport + RedundancyIssue structs:**
   - RedundancyReport: score (f64, 0-100), issues (Vec<RedundancyIssue>), dataset_count (usize), ok_count (usize)
   - RedundancyIssue: dataset_name, criticality, required_copies, actual_copies, required_locations, actual_locations, problems (Vec<String>), suggestion (Option<String>)
   - All derive Debug, Clone, Serialize, Deserialize

3. **analyze_redundancy(datasets: &[Dataset], placements: &[PlacementWithContext]) -> RedundancyReport:**
   - For each dataset, count actual placements (actual_copies) and count DISTINCT node locations (actual_locations). Empty string locations should each count as separate unknown locations.
   - Compare actual_copies vs dataset.min_copies and actual_locations vs dataset.min_locations.
   - Datasets with zero placements get flagged with problem "no placements -- dataset is unplaced".
   - Score = (datasets meeting ALL requirements / total datasets) * 100. If no datasets, score = 100.0 with a note.
   - Include fix suggestion for issues: "add placement on volume in different location" for location issues, "add N more placement(s)" for copy issues.

4. **CapacityReport + CapacityIssue + VolumeProjection structs:**
   - CapacityReport: score (f64), issues (Vec<CapacityIssue>), projections (Vec<VolumeProjection>), skipped_datasets (Vec<String>) -- datasets without growth_rate
   - VolumeProjection: volume_name, node_name, current_used_bytes (i64), ceiling_bytes (i64), monthly_growth_bytes (f64), months_until_full (Option<f64>) -- None if no growth, timeline (Vec<TimelinePoint>) for verbose
   - TimelinePoint: months (i32), projected_bytes (i64), label (String, e.g. "3mo")
   - CapacityIssue: volume_name, node_name, months_until_full (f64), ceiling_bytes (i64), warn_threshold_months (i32)

5. **analyze_capacity(datasets: &[Dataset], volumes: &[Volume], placements: &[PlacementWithContext], warn_months: i32) -> CapacityReport:**
   - For each volume, sum the size_bytes of datasets placed on it (current usage). Sum growth_rate_bytes_month of datasets with growth data placed on it (monthly growth).
   - Ceiling = volume.usable_bytes.unwrap_or(volume.capacity_bytes) -- per locked decision.
   - months_until_full = if monthly_growth > 0 { (ceiling - current_used) / monthly_growth } else { None }.
   - Generate TimelinePoint entries at 3, 6, 12 months.
   - Score = (volumes NOT within warn_months threshold / total volumes with growth data) * 100. Volumes with zero growth data are excluded from scoring (but included in projections with months_until_full = None).
   - Flag datasets on each volume that lack growth_rate as skipped_datasets.
   - Issues = volumes where months_until_full is Some and < warn_months.

6. **Unit tests:** Add `#[cfg(test)] mod tests` with:
   - test_redundancy_all_met: 2 datasets, each with enough copies/locations -> score 100
   - test_redundancy_copies_short: 1 dataset with min_copies=3 but only 1 placement -> score 0, issue reported
   - test_redundancy_locations_short: dataset with min_copies=2 but both on same location -> issue
   - test_redundancy_no_datasets: empty -> score 100
   - test_redundancy_unplaced_dataset: dataset with zero placements -> issue
   - test_capacity_basic: volume with growth, projects correctly
   - test_capacity_no_growth: all datasets lack growth_rate -> projections show None
   - test_capacity_within_threshold: volume full in 6 months, warn at 12 -> issue
   - test_capacity_usable_bytes_precedence: verify usable_bytes is used as ceiling over capacity_bytes

   Tests construct entity structs directly (no DB needed for pure functions). Use `Database::open_memory()` only for `load_placements_with_context` tests.

**src/cli/analyze.rs:** Create this file implementing the CLI layer:

1. **Command structure:**
   ```rust
   #[derive(Subcommand)]
   pub enum AnalyzeCommands {
       /// Check dataset redundancy against min_copies and min_locations requirements
       Redundancy {
           #[arg(long)]
           topology: Option<String>,
           #[arg(long)]
           verbose: bool,
       },
       /// Project capacity usage and estimate time until volumes are full
       Capacity {
           #[arg(long)]
           topology: Option<String>,
           #[arg(long)]
           verbose: bool,
           /// Warn when volume is projected full within N months (default: 12)
           #[arg(long, default_value = "12")]
           warn_months: i32,
       },
   }
   ```
   Note: RPO and Failure subcommands plus the "all" default behavior are added in Plan 02.

2. **`pub fn run(cmd: AnalyzeCommands, db: &mut Database, format: OutputFormat) -> Result<()>`** dispatches to subcommand handlers.

3. **Redundancy handler:**
   - Resolve topology via `resolve_active_topology(db, topology_override)`.
   - Load datasets: `SELECT ... FROM datasets WHERE topology_id = ?1`.
   - Load placements via `load_placements_with_context`.
   - Call `analyze_redundancy(&datasets, &placements)`.
   - **Text output (default/non-verbose):** Print header "Redundancy: {score}% ({issues} issue(s))" using console colors (green >= 100, yellow >= 75, red < 75). Only print issues, not passing datasets. Each issue: "  {dataset_name} [{criticality}]: {problem}" and suggestion if present.
   - **Text output (verbose):** Same header, then ALL datasets: passing ones with green checkmark text "[OK]", failing ones with "[FAIL]" prefix and details.
   - **JSON output:** Serialize the RedundancyReport directly with `serde_json::to_string_pretty`. Include topology name and id wrapper.
   - Exit code 1 if issues found (use `std::process::exit(1)` after printing). Exit 0 if clean.

4. **Capacity handler:**
   - Resolve topology, load datasets, volumes (`SELECT ... FROM volumes WHERE topology_id = ?1`), placements.
   - Call `analyze_capacity(&datasets, &volumes, &placements, warn_months)`.
   - **Text output (default):** Print header "Capacity: {score}% ({N} warning(s))". Only show volumes with issues (approaching threshold). For each issue: "  {volume_name} on {node_name}: full in {months:.0} months ({current}/{ceiling})". Note skipped datasets. Use `Capacity::from_bytes()` for human-readable sizes.
   - **Text output (verbose):** Same header, then timeline table for ALL volumes:
     ```
     Volume        Node       Now         3mo         6mo         12mo        Full
     pool-1        nas-01     2.1/4.0TB   2.4/4.0TB   2.7/4.0TB   3.3/4.0TB   18mo
     ```
     Use yellow for volumes within warn_months, green otherwise. Volumes with no growth show "N/A" for projections.
   - **JSON output:** Serialize CapacityReport with topology wrapper.
   - Exit code 1 if issues found.

5. **Shared helpers in analyze.rs:**
   - `fn load_datasets(db: &Database, topology_id: &str) -> Result<Vec<Dataset>>` -- simple SELECT.
   - `fn load_volumes(db: &Database, topology_id: &str) -> Result<Vec<Volume>>` -- simple SELECT.
   - `fn print_analysis_header(name: &str, score: f64, detail: &str)` -- colored output helper.
   - Use `console::style()` for all coloring. No emoji -- text indicators like [OK], [WARN], [FAIL].
