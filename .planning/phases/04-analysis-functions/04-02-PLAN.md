  <action>
Add to the existing `analysis.rs` file created in Plan 01:

1. **RPO types:**
   - RpoReport: score (f64), issues (Vec<RpoIssue>), datasets_analyzed (usize), datasets_ok (usize), datasets_skipped (Vec<String>) -- datasets without max_rpo_hours
   - RpoIssue: dataset_name, criticality, max_rpo_hours (i32), best_sync_interval_hours (Option<f64>), problem (String), suggestion (Option<String>)
   - SyncRegimeWithContext struct (if not already from Plan 01): sync regime fields + source/target volume names + dataset name. Include a `load_sync_regimes_with_context(db: &Database, topology_id: &str) -> Result<Vec<SyncRegimeWithContext>>` function.

2. **cron_interval_hours(schedule: &str) -> Option<f64>:**
   - Use `croner::Cron::new(schedule)` (or `from_str`) to parse cron expression.
   - Find two successive occurrences from `Utc::now()`.
   - Return gap in hours. Return None if parse fails or no next occurrence.

3. **analyze_rpo(datasets: &[Dataset], placements: &[PlacementWithContext], sync_regimes: &[SyncRegimeWithContext]) -> RpoReport:**
   - Only analyze datasets where max_rpo_hours is Some. Skip others (add to skipped list).
   - For each dataset with max_rpo_hours:
     - Find all sync regimes for this dataset.
     - For each sync regime with a schedule, compute interval via cron_interval_hours().
     - The best (smallest) sync interval across all regimes is the effective RPO.
     - If no sync regimes exist for dataset: issue with problem "no sync regime configured".
     - If sync regimes exist but none have schedules: issue with problem "no scheduled sync (manual only)".
     - If best interval > max_rpo_hours: issue with problem "sync interval ({interval:.1}h) exceeds max RPO ({max_rpo}h)".
     - Include suggestion: "add sync regime with schedule meeting {max_rpo}h RPO" or "increase sync frequency to at most every {max_rpo}h".
   - Score = (datasets_ok / datasets_analyzed) * 100. If no datasets have max_rpo_hours, score 100 with note.

4. **Failure simulation types:**
   - FailureReport: failed_nodes (Vec<String>), volume_impact (Vec<VolumeImpact>), dataset_impact (Vec<DatasetImpact>), summary (FailureSummary)
   - VolumeImpact: volume_name, node_name, capacity_bytes, datasets_hosted (usize) -- volumes on failed nodes
   - DatasetImpact: dataset_name, criticality, severity (FailureSeverity), total_copies (i32), remaining_copies (i32), total_locations (i32), remaining_locations (i32), lost_volumes (Vec<String>)
   - FailureSeverity enum: Lost, Degraded, AtRisk -- derive Debug, Clone, Serialize, Deserialize, PartialEq, Eq, PartialOrd, Ord
     - Lost: remaining_copies == 0 (dataset completely gone)
     - Degraded: remaining_copies > 0 but < original copies (lost some redundancy)
     - AtRisk: remaining copies >= min_copies but remaining locations < min_locations (location requirement broken)
   - FailureSummary: total_volumes_lost (usize), datasets_lost (usize), datasets_degraded (usize), datasets_at_risk (usize)

5. **simulate_failure(failed_node_names: &[String], nodes: &[Node], datasets: &[Dataset], placements: &[PlacementWithContext]) -> Result<FailureReport>:**
   - Resolve failed_node_names to node IDs. Bail with error if any node name not found in the provided nodes list.
   - Find all volumes on failed nodes (from placements' node_id).
   - Volume impact: list of volumes on failed nodes with count of datasets hosted.
   - Dataset impact: for each dataset with at least one placement:
     - Count total copies and locations (across all placements).
     - Count remaining copies and locations after removing placements on failed nodes.
     - Assign severity: Lost if remaining_copies == 0, Degraded if remaining < total, AtRisk if remaining_copies >= min_copies but remaining_locations < min_locations.
     - Only include datasets that are AFFECTED (severity > unaffected). Skip datasets with no placements on failed nodes.
   - Sort dataset_impact by severity (Lost first, then Degraded, then AtRisk).

6. **Unit tests:**
   - test_rpo_all_compliant: dataset with max_rpo=24h, sync regime with "0 */4 * * *" (every 4h) -> score 100
   - test_rpo_violation: dataset with max_rpo=4h, sync with "0 2 * * *" (daily at 2am, ~24h gap) -> issue
   - test_rpo_no_sync: dataset with max_rpo but no sync regime -> issue
   - test_rpo_no_schedule: sync regime exists but schedule is None -> issue
   - test_rpo_skip_no_max_rpo: dataset without max_rpo_hours -> skipped, not scored
   - test_failure_single_node: 2 nodes, dataset on both, fail one -> DEGRADED
   - test_failure_total_loss: dataset only on 1 node, fail that node -> LOST
   - test_failure_multi_node: fail both nodes, dataset on both -> LOST
   - test_failure_at_risk: dataset has 2 copies meeting min_copies=2 but both copies in same location after failure -> AT RISK
   - test_failure_no_impact: dataset not on failed node -> not in results
   - test_cron_interval_hours: "0 */6 * * *" returns approximately 6.0 hours
